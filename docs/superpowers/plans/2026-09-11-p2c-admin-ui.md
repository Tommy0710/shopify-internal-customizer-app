# P2c — Admin UI (Attributes · Products) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the two-tab embedded admin UI (`Attributes`, `Products`) that calls the P2a backend — the first time any of that API becomes reachable by a human.

**Architecture:** Shopify Polaris for the component library (standard for embedded Shopify admin, gives accessibility/consistency for free). App Bridge session tokens via the CDN script already loaded in `src/app/layout.tsx` (`window.shopify.idToken()`) — no App Bridge npm package, to avoid mixing two different App Bridge generations. One `adminFetch` wrapper attaches the token and parses P2a's two error shapes into a typed error. Component tests run under `jsdom` via a per-file `@vitest-environment jsdom` docblock — the main Vitest config stays `environment: "node"` and untouched.

**Tech Stack:** Next.js 14 App Router · React 18 · Shopify Polaris · `@dnd-kit` (drag reorder) · Vitest + `@testing-library/react` (component tests, jsdom) · the P2a REST API

**Spec:** `docs/superpowers/specs/2026-09-08-wk-customizer-redesign-design.md` §12 (admin IA), §8.1 (API surface — now the P2a-shipped version, not the spec's original text)

**Phase this depends on:** P2a (`b31fff4`) — every endpoint this UI calls already exists and is tested. Read `src/lib/admin/*.ts` and `src/app/api/admin/**/route.ts` for exact shapes; do not re-derive them from the spec, which predates P2a's real rulings (flat `GET /products/:id`, `STALE_ORDER`/`HOST_TAKEN`/`NOT_READY`, the full `ReadinessCode` list).

**Explicitly out of scope for this plan:**
- **"Generate variants"** (spec §12.2) — needs P2b (Shopify Admin API calls), which doesn't exist yet. The button renders, disabled, with a tooltip. Wiring it is P2b's job.
- **Production queue** (spec §12.3) — needs `OrderLineDesign` rows, which only exist after P4's webhook lands orders. Not buildable yet.
- Real end-to-end verification inside a live Shopify Admin iframe — nothing in this repo's test suite can drive a real embedded iframe with a real App Bridge session. See the Rulings table for what that means for the `idToken()` assumption.

## Global Constraints

- **Money is always a string, both ways.** Forms send `price` as a string (matches `priceSchema`, e.g. `"80.00"`, `"80"`); the API always returns prices as strings (`formatPrice`). Never round-trip through a JS `number` for currency.
- **`adminFetch` gets a fresh token per call.** App Bridge session tokens are short-lived (~1 minute). Never cache a token across requests; call `window.shopify.idToken()` immediately before each fetch.
- **Two error shapes, one parser.** `422` is `{ errors: [{ field, code, message }] }`; everything else is `{ error: "<CODE>", ...extra }` (`docs: src/lib/admin/http.ts`). `adminFetch` throws one typed error class carrying both shapes; every screen renders it the same way. Never hand-parse a `Response` body outside `adminFetch`.
- **`PUT` screens send the whole desired list, not a diff.** The API does the diffing (`src/lib/admin/diff.ts`); the UI's job is to represent "this is the complete state I want" — checkbox lists, price grids, and the SVG grid are all full-list `PUT`s. A row missing from the list you send gets deactivated server-side (except `ProductHost`, which gets deleted) — the UI must reflect that in its own copy immediately after a successful save, not wait for a refetch to explain what happened.
- **`reorder` requires the exact current active-id set.** Build the payload from the list currently on screen, not from a stale copy — a missing/extra/duplicate id is `409 STALE_ORDER`. On that error, refetch and show a banner ("someone else changed this list — reloaded"), don't retry blindly.
- **Component tests declare `/** @vitest-environment jsdom */` at the top of the file.** Do not touch `vitest.config.ts`'s top-level `environment`; that would flip every hermetic Node test in the repo onto jsdom for no reason.
- **No new state-management or data-fetching library.** `useAdminQuery`/`useAdminMutation` (Task 2) are hand-rolled `useState`/`useEffect` hooks. The API surface is bounded and known; SWR/react-query would be one more thing to keep in sync with `adminFetch`'s error shape for no real gain here.
- **Every list screen shows loading, error, and empty states — not just the happy path.** `AdminErrorBanner` (existing, `src/components/AdminErrorBanner.tsx`) needs a field-error variant for 422s; reuse rather than duplicate.
- **Vietnamese comments and commit messages; identifiers English.** Stage files by explicit path only — never `git add -A`. End every commit message with `Co-Authored-By: Claude Sonnet 5 <noreply@anthropic.com>`.
- **No network calls to real Shopify, Supabase, or Vercel.** No `prisma db push`, no `shopify:deploy`. DB-backed component tests (Task 3 onward, where a screen's behavior depends on real API responses) run `adminFetch` against **route handlers under test via a mocked `fetch`**, not against `npm run test:db`'s real Postgres — the backend is already proven against Postgres by P2a; this phase proves the UI calls it correctly and renders what it gets back, which a mocked `fetch` returning P2a's real JSON shapes does without a second Docker dependency in every UI test run.

## Rulings decided in advance — do not re-litigate

| # | Ruling | Why | Cost if wrong |
|---|---|---|---|
| R1 | **Shopify Polaris**, not a hand-rolled design system | Standard for embedded Shopify admin; matches merchant/staff expectations; gets a11y for free. This is an internal tool, not a marketing surface — no bespoke visual-design pass needed. | Swap the component layer later; page structure/logic unaffected |
| R2 | **No `@shopify/app-bridge-react` package.** Use the raw `window.shopify.idToken()` global that the CDN script (`src/app/layout.tsx`) already exposes | Mixing the legacy 3.x React package with the modern unversioned CDN script is a known source of double-init bugs in embedded Shopify apps. The CDN script is already loaded; adding the React wrapper on top would be two App Bridge instances fighting over the same iframe. | Would need to strip the React package and its Provider tree later |
| R3 | **`window.shopify.idToken()` assumption cannot be proven by this repo's test suite.** Component tests mock it. A manual check inside a real Shopify Admin iframe is required before this ships to users, and is recorded as a follow-up, not skipped silently | No headless browser here can host a real embedded-app iframe with real App Bridge; that infra doesn't exist in this repo and building it is out of scope for a UI phase | If the assumption is wrong, every admin screen fails at first fetch — high visibility, not a silent data-corruption risk |
| R4 | **`@dnd-kit/core` + `@dnd-kit/sortable`** for attribute drag-reorder | Spec §12.1 explicitly requires drag sort. `@dnd-kit` is unopinionated about styling (plays well with Polaris), has no legacy-React-version baggage. | Swap the DnD library later; reorder payload shape (`orderedIds`) doesn't change |
| R5 | **Generate-variants button renders disabled with a tooltip**, not hidden | Spec §12.2 shows it as part of the section header; hiding it would look broken/incomplete rather than "coming later." A disabled control with an explanation is honest about state. | One line of JSX to re-enable once P2b ships |
| R6 | **Everything renders under the single route `/`, client-side.** No new `page.tsx` files under new paths. Tab/product-detail navigation is component state (optionally reflected in the URL via `useSearchParams`/shallow `router.push`, never a real Next.js page transition) | `next.config.mjs`'s CSP `frame-ancestors` header is scoped to exactly `/` (and an inert `/admin/:path*`). A real page navigation to e.g. `/products/abc123` would be served **without** that header — Shopify Admin would refuse to iframe it, and the tab would go blank. Client-side view-switching never issues a new top-level navigation, so no new header rule is needed. | If violated: add a matching `headers()` rule per new route AND verify it inside a real iframe before trusting it — CSP misses like this fail silently until tested in the actual embed |
